How to Verify an APK File's SHA-256 Hash and Scan It with VirusTotal

Downloading an APK from outside the Google Play Store puts the responsibility for checking that file on you. Two checks are especially useful. A SHA-256 hash check tells you whether your file is exactly the file the publisher released, byte for byte. A VirusTotal scan tells you what dozens of security engines think of it. Neither check can prove an app is safe. What they can do is catch tampered downloads, corrupted files and known malware before they reach your phone.

This matters even more with modified apps. Golden WhatsApp is an unofficial, third-party modified WhatsApp APK, not affiliated with Meta or WhatsApp, and using it carries account ban and security risks that are entirely the user's own.

What a SHA-256 hash actually is

SHA-256 is a fingerprint for a file. A mathematical process reads the entire file and produces a string of 64 characters, made of numbers and the letters a to f. Two identical files always produce the same hash, and changing even one byte produces a completely different string.

So if a publisher publishes the official hash next to a download, compute the hash of your copy and compare. If they match exactly, your copy is identical to the publisher's file. If they differ, something changed along the way: the download may be corrupted, incomplete, or deliberately altered.

A match says nothing about whether the original file was trustworthy: a malicious file has a valid hash too. The hash verifies identity, not safety.

Before you start: what you need

  • The APK file itself, downloaded but not yet installed
  • The official SHA-256 hash published by the source, if one is available
  • A Windows, macOS or Linux computer, or your Android phone
  • A web browser for VirusTotal, which needs no account for a basic scan

One honest warning: only compare against a hash on the publisher's own official page. A hash printed on the same random site that gave you the file proves little, because that site can simply print the tampered file's hash. If no trusted official hash exists, skip to the VirusTotal steps and treat the missing hash as a reason for caution.

Step 1: Compute the hash on a computer

A computer is the easiest place to do this: all three major systems have built-in tools, so nothing needs installing.

On Windows, using certutil

  • Open the folder that contains your downloaded APK
  • Click in the folder's address bar, type cmd, and press Enter to open Command Prompt there
  • Type certutil -hashfile filename.apk SHA256, using your file's real name, then press Enter
  • Windows prints the hash as a long string, often with spaces between pairs of characters

Copy that string into a text file for comparison. The spaces are only formatting.

On macOS, using shasum

  • Open Terminal from the Utilities folder inside Applications
  • Type shasum -a 256 followed by a space
  • Drag the APK from Finder into the Terminal window to fill in its path
  • Press Enter, and the hash appears before the file name

On Linux, using sha256sum

  • Open a terminal in the folder holding the APK, or use the file's full path
  • Run sha256sum filename.apk
  • Read the 64-character hash at the start of the output

Step 2: Compute the hash on Android

You can also compute the hash on the phone itself. Android does not show file hashes in its standard settings, so you need a tool: a reputable file manager app with a checksum view showing SHA values, or the Termux terminal app, where sha256sum filename works as on Linux.

Choose carefully: installing an unknown hash-checker app to check an unknown APK defeats the purpose. Prefer a file manager you already trust.

Step 3: Compare the two hashes character by character

Now compare your computed hash with the official hash. This step decides everything, so do not rush it.

  • Compare the full 64 characters, not just the beginning and end
  • Ignore spaces and capitalisation, which some tools add as formatting
  • Work in blocks of eight characters if the string starts to blur together
  • Or use a text editor's find function and let the software confirm the match

If every character matches, your file is the publisher's file. If even one character differs, stop: do not install it, and do not assume the difference is harmless. Delete it.

Step 4: Search the hash on VirusTotal before uploading

VirusTotal is a free service, run by a Google subsidiary, that analyses files with many security engines at once. It keeps a database of files already seen, identified by their hashes, so your privacy-friendly first move is to search by hash before uploading anything.

  • Open virustotal.com and choose Search rather than File
  • Paste the SHA-256 hash you computed and run the search
  • If VirusTotal already knows the file, it shows the existing analysis instantly

Searching by hash uploads nothing, which matters because uploads become available to VirusTotal's security partners.

Step 5: Upload the file if VirusTotal does not know it

If the hash search finds nothing, upload the APK itself using the File option on the VirusTotal home page. Dozens of antivirus engines scan it and results usually appear within a few minutes.

Think before uploading a private file, because uploads are shared with VirusTotal's partners. Once the scan finishes, your real work begins: reading the results properly.

How to read VirusTotal results honestly

What the headline number means

The results page leads with a count: how many engines flagged the file out of the total that scanned it. Zero detections is reassuring, but not proof of safety. Engines only detect what they recognise, and a new harmful file can pass every engine today and be detected next month.

When engines disagree

A small number of detections is the hardest result to judge. One or two flags is often a false positive, especially with mods, because some engines flag repackaging itself or unusual-looking behaviour. But do not dismiss flags unread. A vague label about riskware tells a different story from a specific, named malware family flagged by several well-known engines.

Look beyond the score

The details tabs add context. Check when the file was first submitted, and check the signing information and file name: be suspicious if they do not match what the app claims to be. Community comments are opinions, not verdicts.

What to do if a check fails

  • Hash does not match the official hash: delete the file, do not install it
  • Several respected engines name the same threat: delete the file, do not install it
  • Results are ambiguous: wait, research the detection names, choose caution over curiosity
  • File came from a mirror or a link in a comment: treat that as a risk factor itself
  • Never install a file just because one check passed

A realistic routine before installing any APK

Put together, the routine is simple. Download only from the source you trust most. Compute the hash and compare it with the official value. Search that hash on VirusTotal, upload if needed, and read the full results, not just the headline number.

For an unofficial, third-party mod such as Golden WhatsApp, that decision includes things no scanner can judge. WhatsApp's terms do not permit modified clients, so an account ban is a real possibility, and a third-party build asks you to trust people you cannot audit.

Frequently asked questions

Does a matching SHA-256 hash prove an APK is safe?

No. A matching hash proves your copy is identical to the file the hash was published for. It says nothing about whether that file is trustworthy or free of harmful behaviour.

Does a clean VirusTotal result prove an APK is safe?

No. A clean result means no engine recognised a threat in that file at that time. New or uncommon threats can be missed, and engines cannot judge policy risks such as account bans.

What should I do if my hash is different from the published one?

Delete the file and do not install it. A different hash means a different file, whether the cause was corruption, an incomplete download or tampering.

Why do a few engines flag modified apps when most do not?

Mods are repackaged versions of official apps, and some engines flag repackaging, unfamiliar signatures or unusual permissions automatically. That can produce false positives, but each detection name is still worth reading.
